# Requirements: Guillem Web

**Defined:** 2026-05-04
**Core Value:** The website must immediately signal that Guillem is a highly creative developer with strong technical ability and broad curiosity about the kinds of subjects that power compelling data stories.

## v1 Requirements

Requirements for initial release. Each maps to roadmap phases.

### Landing Experience

- [ ] **LAND-01**: Visitor can load a single-page website with a full-screen hero as the first visible experience.
- [ ] **LAND-02**: Visitor can see Guillem's name presented as the dominant element of the hero.
- [ ] **LAND-03**: Visitor can perceive a distinctive visual style that feels creative and intentional rather than like a generic developer portfolio.

### Interaction

- [ ] **INTX-01**: Visitor can trigger a visible transformation in the hero typography through scrolling.
- [ ] **INTX-02**: Visitor can continue scrolling without the hero interaction breaking readability or navigation.

### Positioning

- [ ] **POSI-01**: Visitor can understand that the site belongs to Guillem as an individual creator/developer.
- [ ] **POSI-02**: Visitor can infer that Guillem is oriented toward data visualization, data journalism, or creative development work from the first-screen experience.
- [ ] **POSI-03**: Visitor can leave with the impression that Guillem has strong creativity, technical craft, and curiosity across multiple subject areas.

### External Presence

- [ ] **LINK-01**: Visitor can open Guillem's GitHub profile from the MVP.

### Technical Foundation

- [ ] **TECH-01**: The MVP runs as a React application.
- [ ] **TECH-02**: The MVP can be deployed on Railway.
- [ ] **TECH-03**: The MVP works on both desktop and mobile browsers.

## v2 Requirements

Deferred to future release. Tracked but not in current roadmap.

### Content Expansion

- **CONT-01**: Visitor can browse a curated project showcase.
- **CONT-02**: Visitor can read an about or point-of-view section explaining Guillem's approach and interests.
- **CONT-03**: Visitor can access direct contact information.

### Long-Form Publishing

- **BLOG-01**: Visitor can read technical or data-story blog posts on the site.
- **BLOG-02**: Visitor can browse archived writing from earlier topics such as security, Git, or TypeScript.

### Richer Interaction

- **RICH-01**: Visitor can experience additional Three.js or 3D elements integrated into the site.
- **RICH-02**: Visitor can experience more extensive microinteractions and motion details beyond the MVP hero.
- **RICH-03**: Visitor can navigate a completed data story or scrollytelling project embedded in the site.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Multi-page portfolio architecture in v1 | Deferred until there is a finished data story or stronger supporting body of work |
| Additional outbound links such as LinkedIn, CV, or email in v1 | The first release should stay tightly focused on the core concept |
| Contact form in v1 | Not needed for the ultra-minimal MVP |
| Blog implementation in v1 | Valuable later, but not part of the narrow initial release |
| Full project grid in v1 | Premature before there is a finished data story to anchor the work |

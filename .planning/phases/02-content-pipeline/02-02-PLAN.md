extension **must** be present in the specifier — an extensionless template literal compiles
cleanly and then fails at prerender with `Cannot find module`. This six-line try/catch is the
entirety of the "two-renderer dispatch": `@next/mdx` derives the format from the file suffix, so

and `findBySlug(entries, slug)` returning the matching entry or `null`.

date-descending `PostEntry[]`; `publishedFor(lang)` returning `selectForLocale(await allPosts(), lang)`;

`isVisible`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL `[slug]` segment → dynamic `import()` | The only request-derived value in the entire phase. It reaches a template-literal module specifier. |
| `content/*.md(x)` front-matter → page metadata and listings | Author-supplied YAML becomes titles, descriptions, `<html lang>` and index entries |
| `NODE_ENV` → published/draft set | A single predicate decides what a production build prerenders |

ASVS V2, V3, V6 and V13 remain inapplicable: no accounts, no sessions, no secrets, no API.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Tampering / Information disclosure | `loadPostModule` template-literal `import()` | mitigate | `findBySlug` allowlists the slug against the enumerated `publishedFor(locale)` list before any import runs; the route contract in Plans 04/05 mandates that order. Turbopack's context module is directory-scoped and a single dynamic segment cannot contain `/`, so this is defence in depth — but it costs one function and removes the class. Asserted by the traversal cases in Task 3. |
| T-02-07 | Tampering | `readdir` target directory | mitigate | `CONTENT_DIR` is `path.join(process.cwd(), "content")`, a module-scope constant. No caller-supplied path reaches `readdir` (ASVS V12). |
| T-02-08 | Input validation | Author-supplied front-matter YAML | mitigate | `assertFrontmatter` throws inside `generateStaticParams`, so a malformed block fails `next build` rather than rendering as visible prose or emitting an empty `<html lang>`. All nine rejection cases are unit-tested (ASVS V5). |
| T-02-09 | Information disclosure | Draft content leaking into a production build | mitigate | `isVisible` reads `NODE_ENV` at call time and is the single predicate; `selectForLocale` is the only listing path. Both environments are unit-tested here and the production build output is asserted in Plan 06. Phase 6's `sitemap.ts` must reuse `publishedFor()` rather than re-deriving the rule. |
| T-02-10 | Repudiation | — | accept | No authenticated actor and no mutation exists; there is nothing to attribute or log. |
</threat_model>

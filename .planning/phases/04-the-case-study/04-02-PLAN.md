<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo content → build-time MDX compile | `content/*.mdx` is repo-controlled input to the compiler. These tests are the gate on what may cross it. |
| author → published prose | Prose ships without human proofreading (the phase's accepted trade). These assertions are the only barrier between a fabricated claim and a live page. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | Information Disclosure | Prose naming or linking the private `ib-gdp-evolution` repository | mitigate | `tests/unit/case-study-content.test.ts` asserts the string `ib-gdp-evolution` and any `github.com` URL are absent from both bodies — the same rule `tests/unit/work.test.ts:37` already binds the work list to. |
| T-04-06 | Spoofing | A fabricated claim presented as the author's own published finding | mitigate | The banned-token and banned-string assertions (`International Baccalaureate`, `World Bank`, `EU-15`) close the three specific fabrications research identified. The verbatim fact check in Plan 06 closes the rest against the Plan 01 snapshots. |
| T-04-07 | Tampering | A `<Figure>` declaring dimensions that disagree with its file, silently regressing BUILD-06 | mitigate | `tests/unit/case-study-figures.test.ts` compares declared attributes against the PNG IHDR header, and `tests/case-study.spec.ts` measures `naturalWidth` from the loaded bitmap. |
| T-04-08 | Elevation of Privilege | An MDX file importing an arbitrary component and widening the render surface | mitigate | The component allowlist assertion restricts both bodies to `Figure` and `Aside`, and the import assertion restricts imports to `@/components/mdx/figure`. Phase 2's own accepted-risk note names this as where Phase 4 drifts from writing into building. |
| T-04-SC | Tampering | npm / pip / cargo installs | accept | No package is installed. Every helper in these three files is hand-written against Node built-ins and the already-present Playwright. |

ASVS V5 (Input Validation) is the applicable chapter and it is satisfied structurally rather than
by new code: `assertFrontmatter` in `lib/content.ts` already throws at build on any malformed
field, and this plan adds assertions ahead of it, not a second parser. V2, V3 and V6 remain
inapplicable — the site is static, read-only, form-free and auth-free, so there is no
authentication, session or cryptography surface for these tests to guard.
</threat_model>

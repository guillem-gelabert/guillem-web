<objective>
The milestone's last artifact. D-4.4 is explicit that the audit is a deliverable, not a ritual: it is
the place where "did we actually build what PROJECT.md described" is answered on the record, row by
row, with evidence. PITFALLS #15 sets its design — check each Out-of-Scope entry **by name**, because
"does this look like generic-portfolio drift" is a judgment call and "is there a card grid" is not.

Three things this plan must get right.

**Live checks, not local ones.** PITFALLS #8 exists because nobody pastes their own localhost link
into Slack. The headers are verified by `curl` against the deploy, not by reading the config —
believing the config is not verification, and D-4.3 requires the post-deploy string be recorded
verbatim.

**The five user-supplied facts go into one artifact, not five scattered notes.** An autonomous run
must be able to build every surface without inventing any of them, and the user must be able to
finish the site by reading one page.

**This plan does not flip robots.** It writes the flip down as an exact procedure, gated by
`tests/unit/launch-gate.test.ts`, for the user to perform after their own review. The user chose to
keep all three copy items blocking: HOME-01's positioning sentence still reads `Developer.`, no human
has read either bylined case study, and `COPY_REVIEWED` is still false. A phase that flipped here
would defeat every tripwire Phases 3, 4 and 5 built.

Purpose: verification against the live deploy, the written audit, and a hand-off that leaves the
milestone finishable in one sitting.
Output: three planning artifacts, one deferred-items record, and a decided `package.json` name.

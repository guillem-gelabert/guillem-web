<objective>
BUILD-04: the site serves a real, fully-justified security header set. This is the milestone's only
genuinely new security surface, and the phase's audience opens dev tools — the omissions matter as
much as the inclusions.

The CSP's hard part is already answered and measured: **there are two inline-style consumers, not
one.** Shiki emits `style="color:#…"` on every token span (shikijs/shiki#671, open) and
`remark-gfm` emits `style="text-align:right"` on aligned table cells — 19 inline style attributes
counted on a real render of the fixture post. Under CSP Level 2+ `style-src 'self'` blocks inline
style *attributes*, so getting this wrong turns every code block on the site into undifferentiated
ink. Fixing Shiki alone would not help; the second consumer is upstream in `remark-gfm`.

Purpose: real headers, an honest written tradeoff, and three independent layers of verification —
because believing the config is not verification.
Output: `lib/csp.ts`, `next.config.ts` `headers()`, and the three test layers.
</objective>

## Trust Boundaries

| Boundary | Description |

| browser → origin responses | The CSP, HSTS and the other four headers are the only policy the browser receives |

# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**No user questions were asked for this spec.** Every item below is either a locked decision from `01-CONTEXT.md` (cited inline as `D-0N`), a resolution of one of CONTEXT's explicit "Claude's Discretion" items (research + recommend, per the researcher's own upstream-input contract), or a direct consequence of `REQUIREMENTS.md`'s Out of Scope table. ## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled semantic HTML + Tailwind v4 utilities. Explicit per `REQUIREMENTS.md` Out of Scope: *"Animation library, state manager, component library — No surface in v1 earns the weight."* Do not run the shadcn init gate; there is nothing to initialize. |
| Icon library | none — Phase 1 ships two routes (holding page, `/type` specimen) with zero icons, zero buttons, zero nav. Revisit only when Phase 3 adds navigation. |
| Font — Display | **Humane** (variable, `wght` 100–900), `next/font/local`, `font-display: optional`. Source: `text_trail_demo/assets/Humane-VF.ttf` → move to `public/fonts/` or `app/fonts/`, unmodified (D-01, licence forbids subsetting). |
| Font — Body/UI | **Newsreader** (variable, Google Fonts, `opsz`+`wght` axes), `next/font/google`, `font-display: swap`. Specific-face pick for D-02's "a text serif" decision — see rationale below. |
| Font — Mono/code | Not decided in Phase 1. Deferred to Phase 2 (code blocks in migrated posts). Do not introduce a third face in Phase 1's two routes. |

**Why Newsreader (D-02 resolution):** the discussion narrowed to "a text serif" (Newsreader/Literata/Source Serif/Spectral) and left the exact face to planning. Newsreader is explicitly modeled on newspaper-style optical-size text — it's the one candidate whose design brief is literally "the register the audience reads in" (graphics editors, newsroom leads), which is the exact rationale the user selected. It ships as one variable file (small payload vs. N static weights, satisfying the STACK.md performance heuristic), has a true italic (needed for case-study pull-quotes in Phase 4), and is non-condensed (satisfies PITFALLS #11's constraint independent of what Humane does). Confirm current axis availability on Google Fonts via `next/font/google`'s typed font list at implementation time.

**Why `font-display: optional` for Humane, `swap` for Newsreader (resolves the discretion item):** Humane is self-hosted, same-origin, 85KB — loads fast, and a fallback-sans substitution at poster scale would look *broken*, not just different (PITFALLS #13's own criterion for choosing `optional`). `optional` means no visible swap flash and zero layout shift once `next/font`'s metric-override fallback is in place — the tightest answer to BUILD-06. Newsreader carries the real reading load (13 posts, case study, CV) and must always end up in the correct face even at the cost of a brief FOUT, so `swap` per PITFALLS #13's explicit recommendation for body copy.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (unused in Phase 1 — no icons) |
| sm | 8px | Compact element spacing (specimen row gaps) |
| md | 16px | Default element spacing (paragraph-to-paragraph on holding page) |
| lg | 24px | Section padding, heading-to-body-line gap |
| xl | 32px | Layout gaps (specimen level-to-level breaks) |
| 2xl | 48px | Major section breaks (specimen page top margin) |
| 3xl | 64px | Page-level spacing |

Exceptions: none. Phase 1 has no touch-target-only UI (no icon buttons, no nav yet) — the 8-pt scale applies throughout both routes without carve-outs.

**Not a spacing exception, noted so it isn't mistaken for one:** the benchmark's ornamental background — a horizontal rule every `12.5vh` (`rgba(23,23,20,0.052)`, from `text_trail_demo/index.html:38-40`) — is a decorative page-texture layer keyed to viewport height, not a layout-spacing token. It is optional polish for this phase (see Aesthetic Guardrails below), not required by any success criterion. Per the project's own working agreement ("MVP first. No polishing until the core works" — `CLAUDE.md`), ship it only after the five Phase 1 success criteria are met.

## Typography

| Role | Size | Weight | Line Height | Face |
|------|------|--------|-------------|------|
| Body | 18px (fixed) | 400 (regular) | 1.6 | Newsreader |
| Label | 14px (fixed) | 600 (semibold) | 1.3 | Newsreader, uppercase, letter-spacing 0.04em |
| Heading | `clamp(2rem, 1rem + 4vw, 4.5rem)` → 32–72px | 800 | 0.9 | Humane |
| Display | `clamp(3.5rem, 1.5rem + 8vw, 11.25rem)` → 56–180px | 800 | 0.82 | Humane |

**Fluid display, fixed body, per D-03.** The two Humane rows are `clamp()` curves so poster-scale type survives to a 375px viewport (verified: at 375px the Display formula bottoms out at its 56px floor, never the demo's fixed 160px `white-space: nowrap` — do not port that literal value or the `nowrap`, D-03 explicitly flags both as incompatible with mobile). Newsreader rows are fixed pixel values so measure and vertical rhythm stay controlled, per D-03.

**Weight discipline — 3 total values, not a violation of "declare exactly 2":** Newsreader (the body/UI face) uses exactly 2 weights, 400/600, as the general rule intends. Humane (the display face) is scoped to a single locked weight, 800 — the value CONTEXT.md's D-01 already validated ("already proven against the trail effect at 160px/0.82 line-height"). Treat Humane's weight as a separate, single, non-negotiable design decision rather than a third entry in the UI-weight budget; do not introduce a second Humane weight (e.g. a lighter 400 for some other Humane usage) without re-running the PITFALLS #11 contrast/legibility check that validated 800.

**Line-height deviates from generic heading guidance (1.2) by design:** Humane is a structural/poster element, not a conventional heading — 0.82/0.9 are tight by intent, ported from the benchmark's validated configuration. This is not an error for the checker to flag; it's the aesthetic (D-01, BRIEF §8 "type as structural element").

**Contrast is resolved by the palette, not by weight tuning:** ink `#171714` on paper `#f2eee5` is near-black on near-white — passes WCAG at any weight/size Humane can produce. PITFALLS #11's contrast risk is real in the abstract but already closed here by the two-tone palette choice; don't spend further effort re-verifying per heading level unless the palette changes.

**Letter-spacing cap (PITFALLS #11):** Humane headings ship at `0em` tracking (matches the benchmark default `--headline-tracking: 0em`) — Humane is already ultra-condensed and doesn't need spacing tricks. The one tracked element in the system is the Label role's uppercase caption text, capped at `0.04em` — well under the range that causes VoiceOver/NVDA to spell words letter-by-letter (documented risk starts appearing at wider values; the benchmark's own debug slider went up to `0.16em` — that slider and its range are a comparison tool, never ship that range). Never exceed `0.04em` tracking on any multi-word real text.

## Motion & Heading Trail Contract (HOME-06 / BUILD-05)

This is the phase's one motion feature. It is a **port, not a rebuild** — the implementation lives at `text_trail_demo/index.html`, and this section fixes the design decisions CONTEXT.md deliberately left open.

### What to port, verbatim

- `createTextShadowEffect()` — `text_trail_demo/index.html:648-688`
- The shared rAF driver `frame()` — `:827-882` (exponential smoothing `1 - exp(-elapsed * 0.009)`, trail clamp, strength curve `min(1, distance / 3)`, settle-below-0.15px-then-stop)
- The `prefers-reduced-motion` early return in `start()` — `:877` (`if (reducedMotion.matches ...) return;`)
- Constants unchanged: `MAX_TRAIL = 280`, `MAX_SHADOWS = 240`, `SCROLL_STOP_DELAY = 120`. **Do not retune these** for v1 — they are the benchmark's validated values; only revisit if a specific visual complaint arises during implementation review.

### What NOT to port

- The debug/comparison chrome: the `.tabs` switcher, `.type-controls` sliders, the `.status` lag/FPS meter. These exist only to compare the three benchmarked techniques side by side and have no role in production.
- The WebGL (`createShaderEffect`) and alpha-mask (`createAlphaMaskEffect`) implementations — text-shadow already won the comparison (D-08/CONTEXT specifics); the other two techniques ship nothing.
- **`trailColor()`'s rainbow hue-cycling** (`:368-390`, driven by `HUE_SPEED = 110` in `handleScroll()`) — see the required deviation below. This is the one place the port must diverge from the source.

### Required deviation: trail color is monochrome ink, not the demo's rainbow cycle

The demo's `frame()` calls `trailColor()` on every frame, which cycles hue based on scroll speed and feeds a shifting `hsl()` value into `draw()`. That is a debug feature for telling the three benchmarked techniques apart at a glance — it is not a production design decision, and shipping it verbatim would put a color-cycling rainbow into a restrained constructivist site, directly contradicting BRIEF principle 3 ("earned motion over introduced motion") and the CONTEXT specifics note that text-shadow "reads as a typographic treatment rather than a set piece."

**Decision:** replace every call to `trailColor()` with a fixed color object equal to the heading's own ink color, `#171714`, solid (no alpha channel). The stacked shadow layers' overlapping sub-pixel offsets already produce the smear/blur illusion through density falloff — alpha blending is not needed and was never how the demo's own smear worked; only the *hue* was decorative. Monochrome ink keeps the effect legible as typography lagging behind itself, not as an ornament layered on top of it.

### Trail scope — which headings carry it

- **Applies to:** every heading set in Humane (the Display and Heading typography roles above) — the holding page's `<h1>Guillem Gelabert</h1>` at Display scale, and every heading level demonstrated at Humane scale on the `/type` specimen route ("the trail at each heading level," D-05).
- **Does not apply to:** serif in-prose subheadings (Newsreader, any level used for structural breaks *within* long-form content — case study sections, migrated posts). Applying a 240-layer stacked shadow to a small in-body subheading would be visually noisy at reading scale and re-introduces the contrast/legibility risk PITFALLS #11 flags, for a treatment that gains nothing there. This is a standing rule for Phase 2+, not just Phase 1 — writing/post pages get the trail only if/when a post title is itself set in Humane (matching the holding page's `<h1>` treatment); in-body prose subheads never carry it.
- **Reduced motion:** the ported `start()` early-return produces a fully static heading — no shadow layers ever computed, default (no) text-shadow. This is the entire BUILD-05 answer for this component; no separate CSS-level motion gate is needed for the trail itself (it's gated in JS before any frame runs).

### Standing rule for all other motion in this phase (PITFALLS #12)

Any hover/focus transition introduced anywhere in this phase's components (there are none required by the two routes' content, but if any interactive affordance is added — e.g. a focus-visible ring) must be wrapped in `@media (prefers-reduced-motion: no-preference)` from the moment it's written, not retrofitted later. This is the standing rule for every phase from here forward, not just Phase 1's own surfaces.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f2eee5` | Page background, all surfaces. Warm off-white, from the benchmark palette (`text_trail_demo/index.html:22-23`), carried forward per CONTEXT's discretion note that it's "a usable starting point." |
| Secondary (30%) | `#171714` | Ink — body text, headings, the heading trail (monochrome, see Motion Contract), the ornamental rule grid if shipped. Near-black, from the same benchmark palette. |
| Accent (10%) | `#C1272D` | Reserved for: focus-visible outline/ring on any interactive element; link hover/underline color once links exist (Phase 2+ writing index, Phase 3+ nav). **Never** the heading trail itself (explicitly monochrome ink, above) and never a background fill. |
| Destructive | not applicable | No destructive actions exist in this phase's scope (static holding page + non-indexed specimen route; no forms, no delete actions). |

**Accent reserved for:** focus rings and link states only, starting from the phase that first introduces a link or focusable element (Phase 1 may ship zero accent pixels — that's not a violation; the reservation exists so later phases inherit a settled answer rather than picking a color ad hoc). `#C1272D` is a Claude's-discretion pick ("constructivist red," echoing the Lissitzky/Rodchenko red referenced directly in BRIEF §8's "Beat the Whites with the Red Wedge") — the hex is adjustable at implementation time; the load-bearing part of this contract is the reserved-for list, not this exact value. Verify at implementation: minimum 3:1 contrast against `#f2eee5` for non-text UI components (focus rings, underlines) per WCAG 1.4.11 — accent is never used for body text, so the stricter 4.5:1 text threshold doesn't apply.

**Dark mode: light-only for v1.** CONTEXT.md flagged this as a genuine open question ("weigh that cost before adding") — resolved here as no, for three concrete reasons: (1) it doubles every contrast check against the heavy Humane display type (PITFALLS #11) for a feature no requirement asks for; (2) it adds scope to a phase whose stated job is "deploy first, then design" (D-08) as fast as possible; (3) the project's own working agreement is explicit — "MVP first. No polishing until the core works" (`CLAUDE.md`). Revisit only if a specific future requirement asks for it.

### Aesthetic Guardrails (BRIEF §8 / PITFALLS #6 — the "looks like data, isn't" trap)

- The benchmark's ornamental horizontal-rule background (`text_trail_demo/index.html:38-40`) — faint (`0.052` alpha) rules every `12.5vh`, no ticks, no numeric labels, no plotted points — passes the checkable rule from PITFALLS #6 ("does this element take a data prop, or is every coordinate hardcoded — and does it read as axis/tick/point"). It's pure hardcoded ornamental geometry, no encoding implied. Safe to carry forward if shipped; it remains optional polish per the Spacing Scale note above, not a requirement.
- Do not add tick marks, axis lines, or plotted-point styling to any decorative element introduced in this phase's two routes. If a future decorative element in this phase's build ever gains an axis-like or tick-like appearance, either strip the signifier or bind it to real data — there is no real data to bind to in Phase 1, so strip is the only available option here.

## Routes & Layout for This Phase

Pre-populated from CONTEXT.md D-05/D-06 — the actual visual deliverable this phase produces.

### `/` — holding page

- One `<h1>` at Display scale (Humane, trail-carrying): **"Guillem Gelabert"**
- One short line of Newsreader Body text beneath it, neutral, no positioning claim, no "in progress"/"under construction" framing (both were explicitly considered and rejected in `01-DISCUSSION-LOG.md` Q4). Suggested exact copy: **"Developer."** — a single factual role-noun, zero adjectives, nothing implying a skill or judgment claim to unwind later (BRIEF §1's allocation principle: engineering is demonstrated, never claimed in copy). This exact wording is adjustable by the executor/planner; the constraint that must hold is: no adjectives, no in-progress language, one short line, Newsreader Body role.
- No navigation, no links, no CTA, no work list, no backlog — all explicitly out of this phase's boundary (HOME-01/03/04 are Phase 3).
- Root metadata carries `robots: { index: false }` per D-07 — not a visual concern, cross-referenced here only so it isn't dropped; Phase 6's FIND-02 plan owns flipping it back.

### `/type` — non-indexed type specimen

- Shows every declared type role (Display, Heading, Body, Label) at its real size/weight/face, each demonstrating the Motion Contract's trail where the role is Humane-set (Display, Heading).
- Includes one Newsreader Body prose block long enough to show line-height/measure in context (a paragraph or two — reuse the holding page's neutral voice; no need to write new copy, placeholder editorial-register text is acceptable here since this route is a reference artifact, not audience-facing copy).
- This route is the reference every later phase's new typographic component gets checked against (CONTEXT specifics) — keep it live and accurate as the system evolves; don't let it drift into a one-time scaffold.
- Not linked from anywhere; accessed directly by URL. `robots: { index: false }` inherited from root metadata (D-07) is sufficient — no separate per-route action needed for this phase.

<objective>
Build the repo-tier half of D-09's two-guard design, and prove it is not vacuous.

Two things make this plan more than boilerplate.

**The blocker.** `node --test` **cannot import a `.tsx` file** — `ERR_UNKNOWN_FILE_EXTENSION`,
reproduced on Node 22.20. Node's type stripping registers `.ts`/`.mts`/`.cts`; JSX needs
transformation, not erasure. D-05 locks the module as `.tsx` and D-09.2 locks a `node --test` check
that reads `LAST_TOUCHED` from it. Both survive if the test reads the module as **source text**,
which is already this repo's shipped idiom for asserting facts about `.tsx`
(`tests/unit/link-contract.test.ts:265-267`) and already its shipped idiom for a shared non-test
reader (`tests/unit/css-source.ts`, `tests/unit/case-study-source.ts`). **Do not add a TS/TSX loader
dependency.** That is the one wrong turn available in this plan.

**The vacuity risk.** Four of the guard's five branches are skips. A `t.skip()` with no message is
indistinguishable from a pass in TAP output, and a guard that silently never runs is worse than no
guard — it reads as protection. Two of the skip conditions are non-obvious and were proved with
fixtures: in a `--depth 1` clone `git log -1 --format=%cs -- <path>` returns **HEAD's date, not the
file's**, and in a linked worktree `.git` is a **file, not a directory** — and executors run in
linked worktrees, so an `existsSync(".git")` probe would skip in exactly the environment this phase
executes in.

Purpose: BACK-02's D-09.2 guard, and BACK-01's shape contract at the repo tier.
Output: one shared reader and two unit test files, plus a recorded demonstration that they fail
when they should.
</objective>

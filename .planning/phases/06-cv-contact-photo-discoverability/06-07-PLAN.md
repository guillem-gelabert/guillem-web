<objective>
FIND-01's textual half, plus the canonical-host decision the user made.

Measured today: `/` serves `<meta name="description" content="Developer.">` and no `og:*` tag at
all — it unfurls as a bare link with no card. `/cv` and `/type` inherit that same `Developer.`
string as their share-preview text. The two root layouts are hand-copied and byte-identical except
for `lang` and one string, each hardcoding `metadataBase`, so every shared metadata concern has two
files to keep in sync.

**The user's decision on the canonical host is settled and this plan implements it.** The apex
`guillemgelabert.com` already serves this exact application byte-identically, via the `guillem-edge`
Cloudflare Worker forwarding to this Railway service — measured, with all paths passing through —
while `rel="canonical"` still points at the Railway hostname. Flipping robots in that state would
make the site crawlable on two hostnames, both declaring the Railway one canonical, and Google would
consolidate onto the generated URL. `lib/site.ts` already reads `NEXT_PUBLIC_SITE_URL`, so this is a
one-variable change, not a cutover, and no domain is detached from any service.

**This plan does not flip robots.** `robots: { index: false }` stays in both root layouts, declared
literally in each file. `tests/unit/launch-gate.test.ts` from plan 06-03 asserts the declarations a
FIND-02 flip must edit are exactly those two — so the factory must not absorb the field, and that
test is what catches it if this plan tries.

Purpose: one metadata source, one hostname, a real title and description on every route, and the
specimen route's own permanent noindex.
Output: `lib/site.ts` extended, `lib/metadata.ts` new, and every route's metadata under the template.
</objective>

<threat_model>
## Trust Boundaries

This is a statically prerendered, read-only, form-free, auth-free site. ASVS V2 (authentication),
V3 (session management), V6 (cryptography) and V13 (API) are genuinely inapplicable — there is no
account, no session, no secret and no request-time input in this plan. The boundaries that exist:

| Boundary | Description |
|----------|-------------|
| npm registry → build | Ten new build-time packages enter the dependency tree and execute during `next build` |
| repo → prerendered HTML | Layout metadata (`robots`, `metadataBase`) decides what search engines are told; a copy-paste split is how such a setting gets silently dropped |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|

No `[ASSUMED]`/`[SUS]`/`[SLOP]` verdict, so no blocking human legitimacy gate applies. Task 1 re-runs `npm audit --audit-level=high` as the gate. Do not re-run `slopcheck install` — it performs a real install and mutates lockfiles. |
| T-02-01 | Information disclosure | `metadata.robots` in the root layout | mitigate | `robots: { index: false }` retained in `app/(en)/layout.tsx` and asserted against the prerendered `/` HTML. Plan 05 must carry it into `app/(de)/layout.tsx`; Plan 06's build-output test asserts it on both locales. |

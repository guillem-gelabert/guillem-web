<interfaces>
<!-- Why the production assertions live in node:test and not Playwright. -->

`playwright.config.ts` starts its `webServer` with `npm run dev`. Every Playwright spec in this
repo therefore observes `NODE_ENV === "development"`, where `isVisible` deliberately returns true
for drafts. Adding a second Playwright project against `next build && next start` would double the
suite's runtime and its failure surface for one assertion class. Instead, the production side is
asserted by reading the prerendered HTML that `next build` writes to `.next/server/app` — which is
exactly how RESEARCH verified `<html lang>` and the Shiki output shape in the first place.

Route-to-file mapping in that directory is a Next internal, so resolve it by walking for `*.html`
and normalising each path (strip the `.html` suffix, and treat a trailing `/index` as the segment
root) rather than hardcoding `writing.html`.
</interfaces>

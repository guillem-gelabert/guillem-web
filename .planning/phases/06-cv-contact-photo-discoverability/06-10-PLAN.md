<objective>
The two automated halves of D-4.4, the milestone's final audit. Both exist because a source-level
gate structurally cannot catch what they catch.

`tests/unit/prose-contract.test.ts` enforces four type sizes, two weights, no literal colours and
`border-radius: 0` — **over `app/globals.css` only**. An arbitrary Tailwind value in a `.tsx` file
(`text-[20px]`, `font-[700]`, `bg-[#eee]`) passes every one of those assertions silently. So does
`<strong>`: Tailwind v4 preflight sets `b, strong { font-weight: bolder }`, which resolves to **700**
outside `.prose-site` — a third weight on screen that no source-level gate can see. Only a rendered
computed-value assertion catches either. This phase adds the first raster image and the first
employment-row layout to the site, and it is the last chance to catch drift before the milestone
closes.

Cross-link integrity is the other half. PITFALLS #15's rule is the design principle: check by name,
mechanically, because "does this look like generic-portfolio drift" is a judgment call while "does
this link 404" is not.

Purpose: the two specs the audit's written verdict cites as evidence.
Output: `tests/cross-links.spec.ts` and `tests/design-budget.spec.ts`.
</objective>

For every element rendered inside `<main>`, read `getComputedStyle` and assert:

- **Weight.** `fontWeight` is in `{400, 530}`. Nothing else. This is the assertion that catches
  `<strong>` resolving to 700 and a `font-[600]` arbitrary value, and it is the only tier that can.
  On failure, report the offending element's tag, classes and text so the fix is one step.
- **Size.** The set of distinct `fontSize` values across all rendered text is at most four at any
  given viewport. Collect them, assert the cardinality, and report the set — the report is what makes
  a future fifth size a one-line diagnosis rather than a hunt. Run this at a single fixed viewport
  and say so; the type scale is `clamp()`-based and comparing across viewports would be meaningless.
- **Radius.** Every `borderRadius` computes to `0px` on all four corners.
- **Accent.** `#C1272D` (as its computed `rgb(193, 39, 45)` form) appears on no element in its
  resting state. Then focus a link and assert the accent *does* appear on the focus ring, and hover a
  link and assert it appears — proving the reservation is a reservation and not an absence. Read the
  expected value from `app/globals.css`'s `@theme` block rather than hardcoding the hex.
- **Icons.** Zero `<svg>` elements and zero `<use>` elements in the rendered DOM on both routes.
- **Non-Latin characters.** The only non-Latin character in rendered text is U+2190 (the back-link
  arrow). Collect the rendered text of both pages, filter to characters outside Basic Latin, and
  assert the resulting set is exactly `{U+2190}`. This catches an arrow glyph or a bullet slipping in
  as decoration.

Additionally, grep-style assertions the CSS unit test cannot make, run as a source sweep inside this
spec's setup rather than as DOM assertions: no arbitrary Tailwind value matching `text-[`, `font-[`,
`bg-[#`, `w-[`, `rounded-` in any `.tsx` under `app/` or `components/`, except where an existing file
already carries one and is explicitly allowlisted with its reason. Build the allowlist from what is
actually in the tree at execution time rather than assuming it is empty, and record any entry found.

Call `page.emulateMedia({ reducedMotion: "reduce" })` before `page.goto()` in any case that touches
hover or focus transitions — Playwright's `reducedMotion` context and test options do not reliably
affect `matchMedia` in this environment, which STATE.md records as a standing rule.

Write the spec's header comment stating precisely what it owns and what it does not: the unit test
owns `app/globals.css`; this spec owns rendered values and JSX, which is where `<strong>` and
arbitrary Tailwind values live. Without that division a future reader deletes one as redundant.

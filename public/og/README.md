# public/og/

These PNGs are the per-post social cards, one per published post per locale
(`{slug}.png`), named directly by each post's `og:image` through
`postOpenGraph()` in `lib/metadata.ts`.

They used to be served by an `opengraph-image.tsx` route in each `[slug]`
segment. Those routes are deleted. A declared `openGraph` object in a page's
metadata overrides the file convention for that segment, so once every route
got an explicit card the convention routes stopped being referenced by
anything and the posts silently fell back to the site-wide cards. Naming the
public path directly is both the fix and the only form an assertion can
check: the convention emits a content-hashed filename no test can name.

**They are committed deliberately, not generated at request time or at
build time by `next/og`.** `next/og`'s bundled Satori cannot load any
variable font — `Humane-VF.ttf` crashes it (`parseFvarAxis`) and takes
`next build` down with it, and Humane's licence forbids instancing it to a
static file to work around that. See
`.planning/phases/06-cv-contact-photo-discoverability/06-RESEARCH.md`
§ FINDING F2 for the full measurement.

**Generated by:** `scripts/capture-brand-images.mjs` (drives Playwright
against the real `app/fonts/Humane-VF.ttf` file and the real design tokens
in `app/globals.css`). The same script also produces the two site-wide
cards (`app/(en)/opengraph-image.png`, `app/(de)/opengraph-image.png`) and
`app/icon.png`.

**Re-run it after publishing a post:**

```
node scripts/capture-brand-images.mjs
```

Two posts today is not a maintenance burden; an undocumented directory of
PNGs would be. If a slug here goes missing or stale, the per-post route
falls back to the locale's site-wide card rather than breaking the build or
serving a broken image URL — but a real per-post card is still the point,
so re-run the script rather than relying on the fallback indefinitely.

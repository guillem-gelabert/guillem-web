<objective>
FIND-01's visual half. `/` currently unfurls as a bare link with no card at all: measured against the
production build, the head carries `og:title`, `og:description`, `og:image`, `og:url`, `og:type`,
`og:site_name`, `og:locale` and every `twitter:*` tag — none of them. Thirteen of those tags arrive
for free from the `opengraph-image` file convention alone, which is why this plan ships the image
and plan 06-07 ships the rest.

**D-3.2's stated mechanism does not survive measurement and must not be attempted.** `next/og`'s
bundled Satori cannot load *any* variable font: `Humane-VF.ttf` and two unrelated variable TTFs all
crash identically at `parseFvarAxis`, and `next build` **fails outright** — a red deploy, not a
degraded card. A control static TTF works, which proves the defect is font-class-specific rather
than `ImageResponse`-wide. Humane's licence forbids modification, so instancing it to a static TTF
is not available either. `06-VALIDATION.md` decision 3 settles it: **committed PNGs captured with
Playwright, in Humane.** Not optional. The same finding kills D-3.5's `app/icon.tsx`; a committed
`app/icon.png` replaces it.

Do not spend time iterating on the card's composition. CLAUDE.md ranks this: the core is that a card
exists, resolves and carries the site's own grammar. Build it, look at it once, move on.

Purpose: every committed brand raster, from one script, with the per-post override D-3.2 asked for.
Output: the capture script, four PNGs plus per-post cards, and the scaffold favicon gone.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| link unfurler → OG image route | Third-party headless browsers fetch these URLs cross-origin |
| build-time slug parameter → `readFile` | A dynamic segment value reaches the filesystem |
| committed font file → capture script | A licence-bearing artifact is read and rendered |
